# 测试环境模组依赖

`run/mods` 现有 69 个 jar，`fabric.mod.json` 声明的依赖都由同级 jar、jar-in-jar 或 `provides` 满足，没有真正缺失的依赖。

## 必须整组禁用的模组

| 组 | 成员 | 原因 |
| --- | --- | --- |
| malilib 系 | malilib、litematica、minihud、itemscroller、tweakermore、tweakeroo、wegui | 后六个都依赖 malilib，wegui 还依赖 litematica |
| Sodium 渲染链 | sodium、sodium-extra、iris | iris 与 sodium-extra 都依赖 sodium |
| Axiom 链 | axiom、dbtools | dbtools 依赖 axiom |
| WorldEdit 链 | worldedit、worldeditcui | 两者共用 worldeditcui_protocol |
| Xaero 地图 | xaerominimap、xaeroworldmap | 共用 xaerolib |
| cloth-config | cloth-config、betterf3、screencopy、modmenu | betterf3 与 screencopy 依赖 cloth-config；modmenu 的界面模块也用它 |

## 可单独禁用的模组

caxton、flashback、continuity、lambdabettergrass、lambdynlights、presencefootsteps、jade、betterf3、jeicharacters、clientcommands、too_many_shortcuts、zoomify、screenshot 系列、carpet 及其附加、jsmacros、magiclib 系。

## 不能禁用

`fabric-api` 被 30 多个模组依赖，`fabric-language-kotlin` 被 Kotlin 模组依赖，两者必须保留。

## provides 与嵌套

- `balm` 提供 `balm-fabric`，clienttweaks 依赖后者。
- `cloth-config` 提供 `cloth-config2`。
- `sodium` 提供 `indium`。
- Fabric API 的 44 个模块、iris 的 5 个、worldedit 的 7 个、worldeditcui 的 9 个等都在各自 jar 内。

## 二分排查建议

1. 先整组禁用 malilib 系，再试 Axiom 链、WorldEdit 链、Xaero。
2. 每次只动一组，保持 Sodium + Iris 不变，才能确认崩溃是否还在。
3. 崩溃与粒子无关，禁模组时不必关本模组。

## 已定位的冲突

在 26.2 + Iris 1.11.4 + Sodium 0.9.2 + BSL 环境下，只保留 malilib、禁用其余 malilib 系模组，进入世界仍会在 Iris 的 `HandRenderer` 透明阶段崩溃：

```text
ArrayIndexOutOfBoundsException: Index 1 out of bounds for length 1
  at GlCommandEncoder.validateDraw
  at PreparedRenderType.wrapBuffer$iris
```

Iris 启动日志对 malilib 的管线只给出 `decent program match`，不是精确匹配。这是 malilib 与 Iris 的兼容问题，与本模组无关。光影环境下排查渲染问题时先禁用 malilib。

补充验证：换用 ComplementaryReimagined r5.9 后同样在 20:04 崩溃；随后禁用 malilib 全家桶、保持同一个光影包，进入世界不再崩溃。两次结果说明问题跟随 malilib，与光影包无关。

结论：光影环境下先禁用 malilib、litematica、minihud、itemscroller、tweakermore、tweakeroo、wegui 这 7 个模组。本模组与其他模组不受影响。
