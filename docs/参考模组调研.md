# 参考模组调研

> 目的：对照成熟粒子模组的设计，确定本项目的下一阶段方向。资料来自公开页面与检索摘要，GitHub 在当前环境不可直连，标“待核实”的条目需要后续确认。

## 1. 结论摘要

| 模组 | 定位 | 值得借鉴 |
| --- | --- | --- |
| [MadParticle 疯狂粒子](https://www.mcmod.cn/class/7482.html) | 面向服务器与数据包的参数化粒子 | 定义放数据包、粒子上限可配、子粒子、逆向播放 |
| [ExParticle](https://www.mcmod.cn/post/4889.html) | 表达式驱动的指令式粒子 | 参数表达式、函数清单可由命令列出、按图片/视频生成 |
| [ColorBlock](https://github.com/Mai-Onsyn/ParticleEffects) 及其衍生 | 指令逐点生成粒子效果 | 生成器与预览工作流 |
| [VortyLib](https://modrinth.com/mod/vortylib) | 公共库 | 自定义 RenderType 配 core shader，并显式适配 Iris |

## 2. MadParticle

- 使用方式：`/madparticle` 指令，参数高度可定制；粒子贴图复用原版或其他模组的粒子纹理，不新增贴图。
- 定义位置：`/customparticle/` 目录下的文件，按约定命名即可新增粒子。
- 粒子上限：设置界面可调，范围 8192 到 1000000，默认 100000。
- 行为：支持子粒子（碰撞后生成新粒子）与元参数 `tenet`（沿轨迹倒放）。
- 性能：页面宣称粒子处理比原版快 10 倍以上。

可借鉴：

1. **定义放数据包或固定目录**，而不是只放 `config`，服务器可以直接随整合包分发。
2. **上限配置化**：我们目前把 8192 和 20000 写死在代码里，应该进配置。
3. **逆向播放**：`tenet` 说明“按负时间采样”是可行且被使用的功能，我们的解析式采样天然支持，只差一个参数。
4. **子粒子**：碰撞或寿命结束时再生成一批粒子，适合烟花、火花四溅。

## 3. ExParticle

- 全部能力挂在 `/particlex` 命令树下，OP 权限；参数支持表达式。
- 表达式变量表示当前粒子状态，可读可写；函数清单由 `/particlex functions` 直接输出。
- 支持根据图片、视频生成粒子布局。

可借鉴：

1. **函数清单可查询**：我们已经用 `/astrorbits schema` 列出了参数，但表达式可用的函数还没有运行时清单，可以在同一个命令里补上。
2. **状态变量可写**：我们的表达式目前只读 `t/d/u/n`，样式参数在绑定期固化。允许写变量会引入状态，和“可跳转”冲突，需要谨慎，不建议直接照搬。
3. **从图片生成布局**：属于编辑器能力，优先级低于运行时正确性。

## 4. ColorBlock 与 ParticleEffects

- 以指令逐点、逐帧生成粒子，配套一个生成器把图案转成指令序列。
- 适合静态图案和烟花，不适合持续演出的参数化特效。

可借鉴：**生成器 + 预览**的工作流。我们的 `/astrorbits test` 只是预设，缺少“改参数立即看效果”的闭环。

## 5. VortyLib 与 Iris

VortyLib 的卖点之一是“自定义 RenderType 配 core shader，并且支持 Iris”。这说明自定义渲染类型在光影下**不是自动兼容**的，需要显式适配。

Iris 侧的机制（据 [ShaderKey 文档摘要](https://deepwiki.com/IrisShaders/Iris/4.1-core-rendering-pipeline)）：Iris 把原版渲染类型映射到 shader pack 的 program；不在映射表里的自定义管线只能回退，配置 `allowUnknownShaders=false` 时会直接报错或表现异常。我们的光影崩溃正属于这一类。

可借鉴：

1. 自定义管线在**启动期**创建并登记，不要等第一次渲染才建；运行中切换光影会重建管线表。
2. 光影下要么按 Iris 的方式注册映射，要么像现在这样退回原版混合。前者需要参考 VortyLib 的实现，属于后续专项。
3. 测试矩阵至少包含：无光影、Iris + BSL、Iris + Complementary、Sodium、AsyncParticles。

## 6. 与本项目对比

| 维度 | 本项目 | 成熟方案 |
| --- | --- | --- |
| 定义来源 | `config/astrorbitsparticle/effects` | 数据包或专用目录，随包分发 |
| 参数 | JSON + 表达式 + schema | 指令参数 + 表达式（ExParticle） |
| 传输 | 服务端下发参数、seed、进度 | 同类做法，MadParticle 也以服务端驱动为主 |
| 渲染 | 自定义 `ParticleGroup` + 批量四边形 | 多数复用原版粒子，VortyLib 走自定义 RenderType |
| 光影 | 自定义 additive 管线，Iris 下退回半透明 | 显式适配 Iris |
| 上限 | 代码常量 | 可配置 |
| 特殊行为 | 无 | 子粒子、逆向播放、碰撞 |
| 工具链 | 测试预设命令 | 生成器、编辑器 |

## 7. 分步计划

1. **P0 光影稳定性**：把自定义管线改为启动期创建；确认 Iris 下不再崩溃；补一份兼容矩阵记录。若要做真叠加，参考 VortyLib 的 Iris 适配。
2. **P1 定义数据包化**：`data/astrorbitsparticle/effects/*.json` + `/reload` 生效，保留 config 作为覆盖层。
3. **P2 上限配置化**：`maxParticles`、`maxVisibleParticles`、`frameBudgetMs` 进配置文件。
4. **P3 逆向与子粒子**：`timeScale` 为负时按负年龄采样；样式结束时按概率生成子特效。
5. **P4 编辑闭环**：`/astrorbits test <preset>` 支持覆盖参数，配合客户端预览命令。
6. **P5 兼容性回归**：固定一组模组组合做启动与渲染冒烟测试。

前两项直接对应已知的光影崩溃与部署方式问题，建议先做。
