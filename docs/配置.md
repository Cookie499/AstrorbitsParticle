# 配置文件

## config.json

路径 `config/astrorbitsparticle/config.json`，两端各自读取，缺失时写入默认值。修改后需要重启。

| 键 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| `maxParticlesPerEffect` | 8192 | 1 到 1048576 | 单个特效的粒子上限，定义里的 `emission.count` 超过时按上限截断 |
| `maxVisibleParticles` | 20000 | 1 到 1048576 | 客户端一帧内计划的粒子总数上限（含轨迹），超出时提高采样步长 |
| `maxVisibleEffects` | 64 | 1 到 1024 | 客户端一帧内渲染的特效数量上限，按距离保留最近的 |
| `frameBudgetMs` | 4.0 | 0.5 到 50 | 客户端单帧采样预算（毫秒），连续超出时自动提高步长 |

`maxVisibleParticles`、`maxVisibleEffects`、`frameBudgetMs` 只在客户端生效；`maxParticlesPerEffect` 只在服务端解析定义时生效。

## 数据包定义

特效定义可以随数据包分发，路径 `data/<namespace>/effects/<name>.json`，id 为 `<namespace>:<name>`。
`config/astrorbitsparticle/effects` 下同 id 的文件覆盖数据包版本，方便服主改参数而不动数据包。

数据包改动后先执行原版 `/reload` 让资源管理器重新扫描，再执行 `/astrorticle reload` 重建定义缓存。

定义里的 `subEffect` 指定另一个定义 id，触发方式由 `subEffectTrigger` 决定：

| 值 | 触发 | 位置 |
| --- | --- | --- |
| `end`（默认） | 本体正常结束 | 本体原点 |
| `impact` | 客户端采样的粒子进入固体方块 | 粒子碰撞点 |
| `particle_end` | 单个粒子消失 | 该粒子消失前的位置 |

`impact` 由客户端每次 tick 按当前采样点检测固体方块，不回溯上一帧位置，快速粒子可能穿过方块。客户端与服务端都对每个源特效报告、生成的子特效数量设上限，避免一次爆发生成过多特效。子特效只展开一层，目标定义自身带 `subEffect` 时忽略，避免递归。

`particle_end` 在服务端按每颗粒子自己的出生/寿命计算消失时刻，并采样它在消失前的位置；不等待整体 `duration`。它只处理非循环、`reverse=false`、`timeScale=1` 且按 `emission` 发射的样式（`comet`、`ambience` 这类连续样式不适用），每个源特效最多取 8 颗粒子（索引均匀取样）。消失时刻按 `appearance.alphaByAge` 与 `sizeByAge` 估算，位置会带父特效的 `scale` 与 `orientation` 旋转。

测试：圆环粒子在 1 秒时消失，8 个位置各生成一发烟花；本体要到 4 秒才结束。

```text
/astrorticle effect play {"style":"astrorbitsparticle:ring_burst","subEffect":"astrorbitsparticle:stage_firework","subEffectTrigger":"particle_end","emission":{"count":8,"lifetime":1},"physics":{"gravity":0},"visibility":{"requireScene":false}}
```
