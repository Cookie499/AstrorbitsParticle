# 粒子样式表

> AstrorbitsParticle · Minecraft 26.2 / Fabric · 样式规范 v1

本表定义模组内置的 9 种粒子样式：每种样式的视觉目标、参数、运动学、随机流、调参预设与 JSON 示例。
架构层面的设计见 [架构设计](架构设计.md)。

**核心约定**：样式只是"运动核 + 参数模式"。发射时机、寿命、物理、外观、轨迹、可见性全部是通用字段，
新增样式时只写样式自己的 `params`，不需要重复实现淡出、着色、批渲染。

## 0. 阅读约定

| 项 | 约定 |
| --- | --- |
| 样式 id | `astrorbitsparticle:<name>`，注册名即本文二级标题的英文名 |
| 时间 | 秒（`duration`、寿命、发射窗口）；内部 tick = 秒 × 20 |
| 距离 | 方块（block） |
| 角度 | JSON 中一律用度；公式中按弧度书写，换算见下 |
| 坐标 | 右手系，Y 轴向上；`origin` 为特效原点 |
| 旋转 | 定义内的本地坐标先绕 Y 轴 `yaw`，再绕 X 轴 `pitch`，最后平移 `origin` |
| 颜色 | `"#RRGGBB"`、`[r,g,b]`、`[r,g,b,a]`，分量 0..1 |
| 数值 | 任何 `num` 字段都可以写成表达式字符串，如 `"6.0 * (1 - 0.3*u)"` |

### 记号

```text
O      特效原点（世界坐标）
t      特效年龄（秒，自播放开始）
d      特效总时长 duration
u      t / d，0..1
i      粒子索引，0 <= i < N
N      粒子总数
life_i  第 i 个粒子的寿命（秒）
h(s,i)  随机流 s 对粒子 i 的取值，[0,1)
h(s,i,k) 同一流上的第 k 次取值（k 从 0 起），用于一个样式需要多个独立随机量的场合
```

公式里的角度一律按弧度书写。JSON 中以度给出的量（`phase`、`angularSpeed`、`spread`、`cone`、`arc`、
`angleJitter`）在实现时先乘 `π/180`。

## 1. 通用模型

### 1.1 定义文件骨架

```json
{
  "style": "astrorbitsparticle:radial_burst",
  "duration": 2.4,
  "loop": false,
  "orientation": "world",
  "emission": { "count": 420 },
  "physics":  { "gravity": 0.0 },
  "appearance": { "sprite": "minecraft:glitter_0", "size": 0.22 },
  "visibility": { "viewDistance": 96.0 },
  "params": { "speed": 6.0 }
}
```

字段解析优先级：**样式默认值 < 定义文件 < 运行时覆盖**。
样式可以覆盖任何通用字段的默认值（例如 `radial_burst` 把 `physics.gravity` 默认设为 0）。

### 1.2 表达式与求值时机

数值字段有两种写法：常量或表达式。表达式用 exp4j 解析，可用变量：

| 变量 | 含义 | 范围 |
| --- | --- | --- |
| `t` | 特效年龄（秒） | `0..d` |
| `d` | 特效总时长（秒） | 常量 |
| `u` | `t / d` | `0..1` |
| `n` | 粒子总数 | 常量 |

内置函数：`abs acos asin atan cbrt ceil cos cosh exp floor log log10 log2 sin sinh sqrt tan tanh`，
常量 `pi`、`e`，运算符 `+ - * / % ^`。另外注册 `clamp(x,a,b)`、`mix(a,b,k)`、`smoothstep(a,b,x)`、
`fract(x)`、`sign(x)`、`step(a,x)`。

**求值时机只有两个，绝不在逐粒子循环里求值：**

1. **常量表达式**（不含 `t`/`u`）：绑定时求值一次，得到 `float`。
2. **时变表达式**（含 `t`/`u`）：绑定时按 `K = clamp(ceil(d*5), 16, 256)` 个采样点烘成查找表，
   运行期只做线性插值。

这条规则是性能与"中途加入即可见"的共同基础，样式实现不得绕过。

### 1.3 随机流

服务端只把 **seed** 发给客户端，不发送随机数本身。每个粒子、每个用途的随机值由
`hash64(seed, stream, index, draw)` 现算，因此同一 `(seed, index)` 在两端、在任何时刻都得到同一结果。

| 流 | 名称 | 用途 |
| --- | --- | --- |
| 0 | `DIR` | 方向、球面采样 |
| 1 | `SPEED` | 速度倍率 |
| 2 | `RADIUS` | 半径、厚度、散布距离 |
| 3 | `PHASE` | 初相位 |
| 4 | `LIFE` | 寿命抖动 |
| 5 | `SIZE` | 尺寸抖动 |
| 6 | `COLOR` | 色相/亮度抖动 |
| 7 | `TIME` | 出生时间、时钟偏移 |
| 8 | `JITTER` | 位置抖动、扩散方向 |
| 9 | `SPRITE` | 贴图变体，只在客户端挑选，不参与服务端计算 |

一个流不够用时用 `draw` 序号续取（`h(s,i,1)`、`h(s,i,2)`…），调用数量与顺序由样式固定，
改动即视为 **RNG 版本变更**。下文样式表里写成 `PHASE(4)`、`SPEED(2)` 的，
表示该流需要取 4 个 / 2 个独立随机量。`SPRITE` 流是纯渲染用途，改动它不影响 `rngVersion`。

### 1.4 发射与寿命

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `mode` | enum | `burst` | `burst` 全部在 t=0 出生；`stream` 在窗口内均匀出生；`random` 在窗口内随机出生 |
| `count` | int | 200 | 粒子总数，上限 8192 |
| `window` | [num,num] | `[0,0]` | 发射窗口（秒），`burst` 忽略 |
| `jitter` | num | 0.0 | 出生时间抖动（秒） |
| `lifetime` | num | 见样式 | 单个粒子寿命（秒） |
| `lifetimeJitter` | num | 0.10 | 寿命抖动比例，± |

粒子 i 的出生时刻与寿命都是索引的闭式函数：

```text
birth_i = window0 + (window1-window0) * birthIndex(i) + jitter*(h(TIME,i)-0.5)
birthIndex(i) = i/max(1, N-1)      // stream
              = h(TIME,i)          // random
              = 0                  // burst
life_i  = lifetime * (1 + lifetimeJitter*(2*h(LIFE,i)-1))
alive_i(t) = t >= birth_i && t < birth_i + life_i
```

**这条闭式定义是"中途加入"能瞬间正确的关键**：任意时刻有哪些粒子在场、各自多大年龄，都能直接算出来，
不需要从 0 重放。

### 1.5 运动积分

所有样式共用一套解析积分。设初速度 `v0`、重力加速度 `g`、线性阻尼 `k`、风场 `w`：

```text
dv/dt = g - k*(v - w)
v∞    = g/k + w
v(t)  = v∞ + (v0 - v∞)*e^(-k*t)
p(t)  = p0 + v∞*t + (v0 - v∞)*(1 - e^(-k*t))/k        (k > 0)
p(t)  = p0 + v0*t + 0.5*g*t²                           (k = 0)
```

对二次/指数项都做了闭式求解，位置永远是 `t` 的函数。

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `gravity` | num 或 vec3 | `-9.8` | 重力加速度，负值向下 |
| `drag` | num | 0.0 | 线性阻尼系数 `k`，1/秒 |
| `wind` | vec3 | `[0,0,0]` | 风场速度 |

样式若自带完整运动学（如 `rain`），可以不读这三个字段，需在样式说明中标注。

### 1.6 外观

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `sprite` | id | `minecraft:generic_0` | 粒子图集中的贴图，也可写原版粒子定义 id（如 `end_rod`） |
| `spriteVariation` | enum | `particle` | `sprite` 指向带多张贴图的原版定义时：`particle` 每颗粒子按 `SPRITE` 流取一张，`effect` 整个特效按 seed 共用一张 |
| `size` | num | 0.20 | 面片边长（块） |
| `sizeJitter` | num | 0.15 | 尺寸抖动比例 |
| `sizeByAge` | curve | `[[0,1],[1,0]]` | 尺寸随归一化年龄的倍率 |
| `color` | color | `#FFFFFF` | 基色 |
| `colorJitter` | num | 0.0 | 色相抖动比例 |
| `colorByAge` | gradient | 无 | 颜色随年龄渐变，覆盖 `color` |
| `alphaByAge` | curve | `[[0,1],[0.7,1],[1,0]]` | 不透明度乘数 |
| `blend` | enum | `additive` | `additive` 发光叠加 / `alpha` 普通混合 |
| `fullbright` | bool | `true` | 忽略世界光照 |
| `stretch` | num | 0.0 | 沿速度方向拉伸的时长（秒），0 关闭；只对能给出速度的样式生效 |
| `spin` | num | 0.0 | 面片自转，度/秒 |

曲线写法 `[[u, value], ...]`，`u` 递增，端点自动钳制，绑定期同样烘成 LUT。
`sizeJitter` 与 `colorJitter` 取 `SIZE` / `COLOR` 流，属于每粒子恒定量，不随时间跳变。

动画精灵（如 `minecraft:vibration`）的帧由贴图集播放：`TextureAtlas` 每 tick 把
`SpriteContents.AnimationState` 的当前帧重绘进该 sprite 在贴图集里的区域，粒子取整块 sprite 的 UV。
因此同一张贴图的所有粒子共享同一帧，没有逐粒子起始帧；原版粒子也是这个行为。
要让动画一眼可见，把 `size` 放到 1 以上，或用 `blend: alpha` 避免叠加发光把细节冲淡。

### 1.7 可见性

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `viewDistance` | num | 96 | 客户端可见距离（块），服务端据此过滤 |
| `requireScene` | bool | true | 是否必须位于演唱会场景内 |
| `boundsPadding` | num | 1.0 | 包围球额外外扩，避免边缘裁切 |

### 1.8 朝向

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `orientation` | enum | `world` | `world` 固定世界坐标；`view` 把局部 +Z 对齐触发时的视线方向 |

`view` 只在生成时取一次视线方向，之后不跟随玩家。旋转绕特效原点进行，样式算出的位置、`stretch` 方向和碰撞检测一起旋转；`bobAmplitude` 的上下方向取局部 Y 轴，会随俯仰一起倾斜。
`/astrorticle effect play` 会带上执行者（玩家或实体）的视线方向，`world` 定义忽略它。

### 1.9 轨迹粒子

`trail` 让客户端在当前年龄之外再按历史时刻采样样式，把历史位置作为额外粒子输出。所有样式共用这一层，样式本身不需要改 `sample`。

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | bool | true | 写 `trail` 对象即启用；false 关闭 |
| `mode` | enum | `time` | `time` 按固定时间间隔回溯；`distance` 按每颗粒子沿路径走过的距离回溯 |
| `interval` | num | 0.1 | `time` 模式每段的回溯间隔（秒） |
| `distance` | num | 0.5 | `distance` 模式每段沿路径的距离（块） |
| `lag` | num | 1.0 | `distance` 模式最长回溯时间（秒） |
| `cap` | int | 8 | 最多几段，不含源粒子，上限 32 |
| `spread` | num | 0.0 | 轨迹段的随机偏移半径（块）：无 drift 时第 k 段取 `spread * k / cap`，有 drift 时从 0 随事件年龄增长到 `spread` |
| `drift` | num | 0.0 | 轨迹粒子沿随机方向的飘散速度（块/秒）；0 时沿历史路径跟随。只用于 time 模式 |
| `sizeScale` | num | 0.8 | 逐段尺寸倍率，第 k 段乘 `sizeScale^k` |
| `alphaScale` | num | 0.7 | 逐段不透明度倍率，第 k 段乘 `alphaScale^k` |
| `color` | color | 无 | 轨迹粒子颜色，缺省继承 `appearance.color`；alpha 仍按段衰减 |

时间模式按固定间隔回溯：

```text
for k = 1..cap:
    age_k   = age - k*interval
    sample_k = sample(style, age_k)       // 只保留 age_k 时刻仍存活的粒子
    p_k     = sample_k.position
    size_k  = sample_k.size  * sizeScale^k
    alpha_k = sample_k.alpha * alphaScale^k
```

存活过滤由样式自己的 `birth` / `life` 完成。轨迹粒子保留源粒子的 `id`；同一发射序号拆成多颗粒子的样式（`comet` 尾迹、`rain` 尾迹）按各自的输出分别处理。

设置 `drift > 0` 后不再逐帧取 `age - k*interval` 的路径点，而是按 `interval` 对齐发射时刻：每个事件取该时刻的源位置，轨迹粒子出生后固定在事件位置，沿由 seed、粒子 id、事件序号决定的随机方向按 `drift` 速度飘散，`spread` 从 0 随事件年龄增长到自身取值。事件年龄超过 `cap*interval` 后消失。这样轨迹不继承源粒子的速度，会向四周散开；`drift=0` 保持原来的路径跟随。distance 模式不使用 `drift`。

距离模式从当前源粒子向过去推进。每帧固定 `2*cap` 个时间探针，探针间隔 `lag/(2*cap)`，逐颗粒子累计路径长度，每走到 `distance` 的整数倍输出一段。`lag` 太短时只能追到较少的段。路径按探针间的直线累计，探针越密越接近真实曲线。

循环特效的历史年龄沿用主采样的周期取模与回溯规则：正向循环只回溯已经开始的周期，非循环式循环（`comet`、`ambience`）与反向播放把负年龄取模到上一周期。反向播放与 `timeScale` 先换算到定义时间再取历史。距离模式按 `id` 只跟踪当前采样中最后一次出现的粒子，遇到周期边界就停止当帧的跟踪链，不跨周期插值；较早周期的同 id 副本没有距离轨迹，循环特效优先用 time 模式。

轨迹继承 `appearance` 的贴图、混合、拉伸与自转；位置、尺寸取自历史采样，颜色默认沿用历史采样，设置 `trail.color` 时改用该 RGB。`spread` 在垂直于该粒子当前运动方向的平面内加随机偏移，查不到当前源粒子时退回水平面。偏移用 `JITTER` 流的高位 draw，由 seed、粒子 id 与段号决定，不改变样式本身的采样输出。轨迹不扩大服务端可见距离和客户端包围球，也不单独做距离判断，是否提交由源特效的 `origin` 决定；轨迹仍计入渲染预算，避免大 `count` 时超过单帧总量。单特效轨迹最多 16384 颗，且不超过 `cap × 当前源粒子数`；超过总量时先丢弃较早的轨迹段。

```json
{
  "style": "astrorbitsparticle:radial_burst",
  "duration": 3.0,
  "trail": {
    "mode": "time",
    "interval": 0.06,
    "cap": 10,
    "spread": 0.25,
    "sizeScale": 0.82,
    "alphaScale": 0.7
  },
  "emission": {"count": 300, "lifetime": 2.0},
  "appearance": {"sprite": "minecraft:glitter_0", "size": 0.3, "color": "#FFD36E"},
  "visibility": {"requireScene": false},
  "params": {"speed": 8.0}
}
```

轨迹把单帧样式采样次数提高到 `cap+1` 次，粒子数最多到源粒子的 `cap+1` 倍，并受单特效 16384 颗轨迹上限约束。`cap` 与 `count` 同时调大时先降 `count`；渲染预算按含轨迹的粒子数计算，见 [架构设计](架构设计.md) 8.4。

## 3. 样式详解

参数的类型、默认值与取值范围以 [样式参数](样式参数.md) 为准；该表由代码里的样式声明生成。
本节保留运动学、随机流与调参说明。

### 3.1 `radial_burst` 放射状爆发

**视觉目标**：从一个点炸开，粒子沿直线射向四面八方，速度有轻微差异，形成"射线束"而不是均质球壳。
适合开场第一击、鼓点重音。

**参数**

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `speed` | num | 6.0 | 基准速度（块/秒），可写表达式做整体加速/减速 |
| `speedJitter` | num | 0.12 | 速度差异比例，0 为理想球壳，0.3 以上会很散 |
| `originJitter` | num | 0.0 | 原点抖动半径（块），做出"有体积的爆点" |
| `axis` | vec3 | `[0,1,0]` | 主方向，只影响 `cone` 模式 |
| `cone` | num | 180.0 | 喷射半角（度），180 为全向，小于 180 时向 `axis` 聚拢 |
| `shellBias` | num | 0.0 | 速度分布向快端偏移，0 均匀，1 全部取上限 |
| `bobAmplitude` | num | 0.0 | 沿世界 Y 轴的上下波动幅度（块），0 关闭 |
| `bobPeriod` | num | 1.2 | 上下波动周期（秒），按粒子自身年龄计 |

**运动学**

```text
dir_i   = uniformSphere(h(DIR,i))                       // cone=180
        = coneAround(axis, cone, h(DIR,i))              // cone<180
speed_i = speed * (1 + speedJitter*(2*h(SPEED,i)-1)) * (1 + shellBias*h(SPEED,i,2))
bob_i   = bobAmplitude * sin(2π*local_i/bobPeriod + 2π*h(PHASE,i))
p_i(t)  = O + jitterSphere(originJitter) + dir_i*speed_i*local_i + 0.5*g*local_i²
          + (0, bob_i, 0)                               // local_i = t - birth_i
```

`coneAround` 采用立体角均匀采样，否则小角度时边缘会明显堆积：

```text
cosθ = 1 - h1*(1 - cos(cone))
θ = acos(cosθ),  φ = 2π*h2
dir = axis*cosθ + e1*sinθ*cosφ + e2*sinθ*sinφ      // e1,e2 为 axis 的正交基
```

**随机流**：`DIR`、`SPEED`、`SPEED(2)`、`PHASE`、`LIFE`、`SIZE`、`COLOR`、`JITTER`

**预设**

| 名称 | 关键参数 |
| --- | --- |

### 3.2 `spherical_burst` 球状爆发

**视觉目标**：均匀向四周扩散并形成一个球体，球体在重力下整体下坠、下缘被压扁。
`fill=0` 得到空心壳（爆开瞬间的冲击波感），`fill=1` 得到实心球（体积感、云团感）。

**参数**

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `speed` | num | 5.0 | 球面最大速度（块/秒） |
| `fill` | num | 0.0 | 0 空心壳 / 1 实心球，中间值介于两者 |
| `shellJitter` | num | 0.03 | 壳层厚度抖动，`fill=0` 时生效 |
| `flatten` | num | 1.0 | Y 轴压扁系数，0.6 会得到一个扁球 |
| `originJitter` | num | 0.0 | 原点抖动半径 |

**运动学**

```text
dir_i   = uniformSphere(h(DIR,i))
o_i     = O + jitterSphere(originJitter)          // 爆点自身的体积
c       = h(SPEED,i)
speed_i = speed * mix(1 + shellJitter*(2*c-1), cbrt(c), fill)
disp_i  = dir_i*speed_i*t + 0.5*g*t²
p_i(t)  = o_i + (disp.x, disp.y*flatten, disp.z)
```

`cbrt(c)` 让速度按体积均匀分布，t 时刻的粒子密度在球内均匀，这是"实心球"而非"更厚的壳"的原因。

**随机流**：`DIR`、`SPEED`、`LIFE`、`SIZE`、`COLOR`、`JITTER`

**预设**

| 名称 | 关键参数 |
| --- | --- |
| 冲击波壳 | `fill=0, speed=16, shellJitter=0.01, count=500, lifetime=0.9` |
| 实心能量球 | `fill=1, speed=6, gravity=-2.5, count=900, lifetime=2.2` |
| 下坠烟球 | `fill=1, speed=3.5, gravity=-6.0, drag=0.6, flatten=0.8` |

**示例**

```json
{
  "style": "astrorbitsparticle:spherical_burst",
  "duration": 2.6,
  "emission": { "count": 900, "lifetime": 2.2, "lifetimeJitter": 0.2 },
  "physics": { "gravity": -2.5, "drag": 0.15 },
  "appearance": {
    "sprite": "minecraft:glow",
    "size": 0.34,
    "sizeByAge": [[0, 1.0], [0.4, 1.5], [1, 0.2]],
    "color": "#7FD4FF",
    "alphaByAge": [[0, 0.9], [0.5, 0.6], [1, 0.0]],
    "blend": "additive"
  },
  "params": { "speed": 6.0, "fill": 1.0, "flatten": 0.85 }
}
```

**备注**

- `drag` 会让球体提前"停住"并向中心回缩，视觉上是先膨胀后悬停，适合慢歌。
- 与 3.1 的区别：这里是**体积均匀**且**受重力**；3.1 是**恒定速度的直线**且默认无重力。

### 3.3 `ring_burst` 环形爆发

**视觉目标**：粒子只在某个平面内扩散，形成一个边界清晰的环，带轻微下坠和轻微差速。
默认水平环（地面冲击环），可用 `planeNormal` 立起来做竖直光环。

**参数**

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `planeNormal` | vec3 | `[0,1,0]` | 环所在平面的法线 |
| `speed` | num | 6.0 | 径向速度（块/秒） |
| `speedJitter` | num | 0.08 | 差速比例 |
| `thickness` | num | 0.0 | 环的厚度（沿法线，块） |
| `radius0` | num | 0.0 | 初始半径，>0 时从既有圆环向外扩张 |
| `even` | bool | true | true 为等角度分布，false 为随机角度 |
| `angleJitter` | num | 0.0 | 等角度分布上叠加的角度抖动（度） |
| `arc` | num | 360.0 | 圆弧张角，小于 360 得到扇环 |

**运动学**

```text
n = normalize(planeNormal), (e1,e2) = orthoBasis(n)
ang_i = rad(arc) * (even ? i/max(1, N-1) : h(DIR,i))
        + angleJitter*(h(PHASE,i)-0.5)
dir_i = e1*cos(ang_i) + e2*sin(ang_i)
speed_i = speed * (1 + speedJitter*(2*h(SPEED,i)-1))
p_i(t) = O + dir_i*(radius0 + speed_i*t) + n*thickness*(h(RADIUS,i)-0.5) + 0.5*g*t²
```

`g` 的投影会自然把环压成椭圆并轻微下沉，这正是"略微下坠"的来源。

**随机流**：`DIR`（随机角）、`PHASE`、`SPEED`、`RADIUS`、`LIFE`、`SIZE`

**预设**

| 名称 | 关键参数 |
| --- | --- |
| 地面冲击环 | `planeNormal=[0,1,0], speed=10, thickness=0.2, gravity=-1.5, count=400` |
| 竖直光环 | `planeNormal=[0,0,1], speed=5, arc=300, even=true` |
| 缓慢扩散环 | `speed=1.2, speedJitter=0.02, lifetime=4.0, gravity=0` |

**示例**

```json
{
  "style": "astrorbitsparticle:ring_burst",
  "duration": 2.8,
  "emission": { "count": 420, "lifetime": 2.4, "lifetimeJitter": 0.1 },
  "physics": { "gravity": -1.5 },
  "appearance": {
    "sprite": "minecraft:spark_0",
    "size": 0.24,
    "color": "#B388FF",
    "alphaByAge": [[0, 1.0], [0.75, 0.8], [1, 0.0]],
    "stretch": 0.018
  },
  "params": { "planeNormal": [0, 1, 0], "speed": 10.0, "thickness": 0.2 }
}
```

**备注**

- `even=true` 加高 `count` 会得到非常干净的环；不想要"机械感"就调 `angleJitter` 到 5–15°。
- 环与球同时播放（同一原点、各自独立 seed）是常见的"冲击波 + 碎屑"组合。

### 3.4 `fountain` 喷泉

**视觉目标**：从一个点沿某个方向持续喷出，粒子呈锥形散开，在重力下划出抛物线回落。
`params.speed` 可以随时间变化，做出"涌起—衰减—再涌起"的呼吸式喷射。

**参数**

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `axis` | vec3 | `[0,1,0]` | 喷射主方向 |
| `spread` | num | 18.0 | 圆锥半角（度） |
| `speed` | num | 8.0 | 初速度（块/秒），可写 `t` 表达式 |
| `speedJitter` | num | 0.12 | 每粒子速度差异 |
| `nozzleRadius` | num | 0.10 | 喷口半径（块），粒子在喷口球内随机取起点 |

**运动学**

```text
dir_i   = coneAround(axis, spread, h(DIR,i))
v_i     = speed(t = birth_i) * (1 + speedJitter*(2*h(SPEED,i)-1))
nozzleOffset_i = uniformInSphere(nozzleRadius, h(JITTER,i), h(RADIUS,i))
p_i(t)  = O + nozzleOffset_i + dir_i*v_i*(t-birth_i) + 0.5*g*(t-birth_i)²
          (t < birth_i 时不存在)
```

注意 `speed` 在**粒子出生时刻**求值并固化：喷口速度变化表现为不同批次粒子初速不同，而不是已飞出的粒子中途加速。
这既是物理正确的，也保证中途加入的客户端能复现同一批粒子的速度。

**随机流**：`DIR`、`SPEED`、`TIME`、`LIFE`、`SIZE`、`COLOR`

**预设**

| 名称 | 关键参数 |
| --- | --- |
| 广场水柱 | `speed=9, spread=8, gravity=-9.8, count=400, lifetime=2.4` |
| 呼吸喷泉 | `speed="6 + 4*sin(2*pi*t/4)", spread=14, count=600, lifetime=2.0` |
| 光柱喷发 | `speed=16, spread=5, gravity=-3, count=300, lifetime=1.6, sprite=end_rod` |

**示例**

```json
{
  "style": "astrorbitsparticle:fountain",
  "duration": 8.0,
  "emission": {
    "mode": "stream",
    "count": 600,
    "window": [0.0, 7.2],
    "lifetime": 2.2,
    "lifetimeJitter": 0.12
  },
  "physics": { "gravity": -9.8, "drag": 0.05 },
  "appearance": {
    "sprite": "minecraft:splash_0",
    "size": 0.18,

    "sizeByAge": [[0, 0.7], [0.2, 1.0], [1, 0.6]],
```

**备注**

### 3.5 `spiral` 螺旋

**视觉目标**：粒子绕中心轴旋转并沿轴推进，形成螺旋；粒子一边前进一边向四周随机扩散，越走越散。
半径、角速度、轴向速度都可以随时间变化，`phase` 用于整体相位偏移。

**参数**

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `axis` | vec3 | `[0,1,0]` | 螺旋轴 |
| `radius` | num | 1.6 | 旋转半径（块），可写表达式 |
| `radiusJitter` | num | 0.04 | 半径抖动比例 |
| `angularSpeed` | num | 180.0 | 角速度（度/秒），可写表达式；负值反向旋转 |
| `axialSpeed` | num | 0.9 | 轴向速度（块/秒），可写表达式 |
| `phase` | num | 0.0 | 全局初相位（度） |
| `phaseJitter` | num | 6.0 | 每粒子相位抖动（度） |
| `strands` | int | 1 | 螺旋股数，2 即双螺旋 |
| `scatter` | num | 0.0 | 径向随机扩散速度（块/秒） |
| `scatterGrowth` | num | 1.0 | 扩散随年龄的指数，1 线性、2 加速 |

**运动学**

```text
strand_i = i % strands
θ_i(t)   = rad(phase + 360*strand_i/strands + phaseJitter*(h(PHASE,i)-0.5))
           + ∫0^t angularSpeed(s) ds              // 表达式时用累积 LUT
r_i(t)   = radius(t) * (1 + radiusJitter*(2*h(RADIUS,i)-1))
z_i(t)   = ∫0^t axialSpeed(s) ds
p_i(t)   = O + (e1*cosθ_i + e2*sinθ_i)*r_i + axis*z_i
           + unitVec(h(JITTER,i))*scatter*(t/d)^scatterGrowth
```

`angularSpeed`/`axialSpeed` 为表达式时，绑定期把 `∫` 预积分成与时间采样的 LUT 再累加，
逐粒子只做查表，不会出现每个粒子各算一次积分的情况。

**随机流**：`PHASE`、`RADIUS`、`JITTER(2)`、`LIFE`、`SIZE`

**预设**

| 名称 | 关键参数 |
| --- | --- |
| 双螺旋 | `strands=2, radius=1.8, angularSpeed=170, axialSpeed=1.1, phaseJitter=2` |
| 扩散光柱 | `radius=0.6, angularSpeed=260, axialSpeed=2.4, scatter=1.2, scatterGrowth=2` |
| 收束螺旋 | `radius="2.4 - 0.8*u", angularSpeed=140, axialSpeed=0.6` |

**示例**

```json
{
  "style": "astrorbitsparticle:spiral",
  "duration": 6.0,
  "emission": { "count": 1200, "lifetime": 5.0, "lifetimeJitter": 0.06 },
  "physics": { "gravity": 0.0 },
  "appearance": {
    "sprite": "minecraft:end_rod",
    "size": 0.16,
    "color": "#8AF0FF",
    "alphaByAge": [[0, 0.0], [0.08, 1.0], [0.75, 0.9], [1, 0.0]],
    "blend": "additive"
  },
  "params": {
    "axis": [0, 1, 0],
    "radius": 1.8,
    "angularSpeed": 170.0,
    "axialSpeed": 1.1,
    "strands": 2,
    "phase": 0.0,
    "phaseJitter": 2.0,
    "scatter": 0.15,
    "scatterGrowth": 1.5
  }
}
```

**双螺旋怎么摆**

- **正解（同向）**：`strands=2`，两股相位差 180°、角速度相同，任一高度上两股恰好相对，即 DNA 型双螺旋。
- **反向（麻花）**：如果让两股角速度相反，`θA = ωt`、`θB = π - ωt`，在 `ωt = π/2` 处两股会重合，
  视觉上是交替交叉的"麻花"而不是双螺旋。要复现该效果就用两个 `strands=1` 的特效，
  分别设 `angularSpeed` 为 `+ω` 与 `-ω`，并给第二个特效的 `origin` 沿轴偏移半个螺距。

**备注**

- `phaseJitter` 别超过 15°，否则两股的"辫子"结构会糊掉。
- 中途加入时 `θ` 与 `z` 都是时间的闭式函数，直接采样即可。

### 3.6 `wave` 波浪

**视觉目标**：粒子沿正弦曲线运动，形成一条（或一片）起伏的波带；曲线整体可以平移，
粒子也可以相对曲线滑动。适合做横贯舞台的"能量波纹"。

**参数**

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `travelAxis` | vec3 | `[1,0,0]` | 波的传播方向（水平面内） |
| `amplitude` | num | 0.9 | 振幅（块） |
| `wavelength` | num | 5.0 | 波长（块） |
| `flowSpeed` | num | 3.0 | 粒子沿曲线的流动速度（块/秒） |
| `driftSpeed` | num | 0.0 | 整条曲线沿 `travelAxis` 的平移速度（块/秒） |
| `phase` | num | 0.0 | 初相位（度） |
| `width` | num | 16.0 | 波带长度（块） |
| `depth` | num | 1.0 | 波带宽度（块），>0 时在垂直方向铺多排 |
| `rows` | int | 1 | 横向排数，>1 得到"波面"而非"波线" |
| `jitter` | num | 0.05 | 位置随机抖动（块） |

**运动学**

```text
row_i   = i % rows,  col_i = i / rows,  cols = ceil(N/rows)
s_i     = col_i / max(1, cols-1)                              // 沿波带的归一化位置
x_i(t)  = O.x + width * fract(s_i + flowSpeed*t/width)        // 沿传播方向流动并循环
k       = 2π / wavelength
rowPhase_i = rows > 1 ? π*row_i/(rows-1) : 0                    // 排间相位滞后，形成波面
y_i(t)  = O.y + amplitude*sin(k*(x_i - driftSpeed*t) + rad(phase) + rowPhase_i)
rowDepth_i = rows > 1 ? depth*(row_i/(rows-1) - 0.5) : 0
z_i(t)  = O.z + rowDepth_i + jitter*(h(JITTER,i)-0.5)
```

- `flowSpeed = driftSpeed` 时粒子相对曲线静止，整个正弦形状随粒子一起平移，看到的是纯行波；
- `flowSpeed > driftSpeed` 时粒子在波面上向前滑动，像"冲浪"；
- `driftSpeed = 0` 时曲线本身不平移，只有粒子沿曲线滑动。

**随机流**：`JITTER`、`LIFE`、`SIZE`、`COLOR`

**预设**

| 名称 | 关键参数 |
| --- | --- |
| 单条行波 | `amplitude=1.2, wavelength=6, flowSpeed=4, rows=1, count=300` |
| 波面 | `rows=6, depth=6, amplitude=0.8, wavelength=4, count=900` |
| 驻波呼吸 | `flowSpeed=0, driftSpeed=0, amplitude="0.4 + 0.6*sin(pi*t/2)"` |

**示例**

```json
{
  "style": "astrorbitsparticle:wave",
  "duration": 7.0,
  "emission": { "count": 500, "lifetime": 7.0, "lifetimeJitter": 0.0 },
  "physics": { "gravity": 0.0 },
  "appearance": {
    "sprite": "minecraft:glow",
    "size": 0.22,
    "color": "#66E0FF",
    "alphaByAge": [[0, 0.0], [0.1, 0.9], [0.9, 0.9], [1, 0.0]]
  },
  "params": {
    "travelAxis": [1, 0, 0],
    "amplitude": 1.2,
    "wavelength": 6.0,
    "flowSpeed": 4.0,
    "driftSpeed": 4.0,
    "width": 18.0,
    "rows": 3,
    "depth": 4.0
  }
}
```

**备注**

- `fract()` 循环会让粒子在波带末端瞬移回起点；把 `width` 设得比 `viewDistance` 大，
  或者让两端落在观众视野外，就不会被看到。
- 中途加入时 `x_i(t)` 依赖 `fract`，但仍是 `t` 的闭式函数，结果一致。

### 3.7 `comet` 彗星

**视觉目标**：一个明亮、偏大的主体粒子沿抛物线飞行，身后拖着一条随时间逐渐扩散、逐渐变暗的尾迹。
适合"从天而降的开场"或"绕场一周"。

**参数**

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `velocity` | vec3 | `[0,5,0]` | 主体初速度（块/秒） |
| `headScale` | num | 3.0 | 主体尺寸相对 `appearance.size` 的倍数 |
| `headColor` | color | 无 | 主体颜色，缺省用 `appearance.color` |
| `headGlow` | num | 1.0 | 主体额外提亮系数 |
| `tailCount` | int | 90 | 尾迹粒子数（`emission.count` 被忽略，总数 = 1 + `tailCount`） |
| `tailLag` | num | 0.9 | 尾迹最长滞后时间（秒） |
| `tailSpread` | num | 0.40 | 最大扩散半径（块） |
| `tailSpreadGrowth` | num | 1.6 | 扩散随滞后的指数，>1 表示越靠后越散 |
| `tailWobble` | num | 0.06 | 尾迹低频抖动幅度（块） |
| `tailFade` | num | 1.4 | 尾部亮度衰减指数 |

**运动学**

```text
主体：p_head(t) = O + velocity*t + 0.5*g*t²

尾迹第 j 个粒子：
τ_j      = tailLag * ((j+1)/tailCount)
base_j   = p_head(t - τ_j)                       // 取主体过去的位置
spread_j = tailSpread * (τ_j/tailLag)^tailSpreadGrowth
φ_j,k    = 2π*h(PHASE, j, k)                     // k = 0,1,2，三条轴各一个相位
wobble_j = tailWobble * (sin(3.1*t + φ_j,0), sin(2.7*t + φ_j,1), sin(3.7*t + φ_j,2))
p_j(t)   = base_j + unitVec(h(JITTER,j))*spread_j + wobble_j
alpha_j  = (1 - τ_j/tailLag)^tailFade
```

尾迹不是逐帧发射的粒子，而是**固定滞后采样点**：任何时刻都能直接由 `t` 求出整条尾巴，
所以中途加入的客户端看到的是完整尾迹，而不是一条光秃秃的主体。

**随机流**：`JITTER`、`PHASE`、`SIZE`、`COLOR`

**预设**

| 名称 | 关键参数 |
| --- | --- |
| 坠落彗星 | `velocity=[0,-2,0], gravity=-9.8, tailLag=1.4, tailSpread=0.9` |
| 掠场彗星 | `velocity=[0,3,12], gravity=-6, tailLag=0.8, tailSpread=0.35` |
| 悬停光球 | `velocity=[0,0,0], gravity=0, tailLag=0.6, tailSpread=0.5, tailWobble=0.12` |

**示例**

```json
{
  "style": "astrorbitsparticle:comet",
  "duration": 4.5,
  "emission": { "count": 1, "lifetime": 4.5, "lifetimeJitter": 0.0 },
  "physics": { "gravity": -6.0 },
  "appearance": {
    "sprite": "minecraft:glow",
    "size": 0.3,
    "color": "#FFE9A8",
    "alphaByAge": [[0, 1.0], [0.85, 1.0], [1, 0.0]],
    "blend": "additive"
  },
  "params": {
    "velocity": [0, 3, 12],
    "headScale": 3.5,
    "headColor": "#FFFFFF",
    "tailCount": 120,
    "tailLag": 0.8,
    "tailSpread": 0.35,
    "tailSpreadGrowth": 1.6,
    "tailWobble": 0.06
  }
}
```

**备注**

- `headScale` 生效时，主体的 `size` 会再乘 `sizeByAge(0)`，两者别同时压得太小。
- 尾迹粒子的 `alpha` 由 `tailFade` 决定，`appearance.alphaByAge` 仍然会再乘一次，
  通常把 `alphaByAge` 设为 `[[0,1],[1,1]]` 交给 `tailFade` 控制更直观。
- `comet` 自带 `tailCount` 尾迹；再开 `trail` 会给主体和每颗尾迹粒子各加一层轨迹，通常只保留一种。

### 3.8 `ambience` 氛围

**视觉目标**：在一大片体积内稀疏散布的粒子，缓慢随机移动、上下浮动、随机明灭。
它是"常驻背景"，用于填充舞台空间、增强纵深，本身不应该抢注意力。粒子在 `duration` 内随机错开出生，不会整批同时出现；循环时持续补充，不按周期整批重置。

**参数**

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `box` | vec3 | `[18,8,18]` | 分布体积（块） |
| `mode` | enum[] | `["drift","bob","flicker"]` | 可组合的行为：随机游走 / 上下浮动 / 明灭 |
| `driftSpeed` | num | 0.15 | 漂移频率（Hz），越大越"活" |
| `driftAmplitude` | num | 1.2 | 漂移幅度（块） |
| `bobAmplitude` | num | 0.5 | 浮动幅度（块） |
| `bobPeriod` | num | 7.0 | 浮动周期（秒） |
| `flickerRate` | num | 0.08 | 明灭频率（Hz） |
| `visibleFraction` | num | 0.65 | 同时可见的比例 |

**运动学**

```text
birth_i  = burst: [window0, window1] 内随机；window 为 [0,0] 时取 [0, duration]
           stream/random: EmissionMath.birth
life_i   = EmissionMath.lifetime
local_i  = t - birth_i
base_i   = O + (h(JITTER,i)*box - box/2)                 // 体积内均匀分布
drift_i  = driftAmplitude * ( sin(2π*f1_i*local_i + φ1_i),
                              sin(2π*f2_i*local_i + φ2_i),
                              sin(2π*f3_i*local_i + φ3_i) )   // 三轴独立低频正弦
bob_i    = bobAmplitude * sin(2π*local_i/bobPeriod + φ4_i)
p_i(t)   = base_i + drift_i + (0, bob_i, 0)               // local_i 不在 [0, life_i) 时不出生

可见性：gate_i(local) = fract(h(TIME,i) + local*flickerRate)
        visible  = gate_i(local) < visibleFraction
        alpha    = smoothstep(0, 0.15, gate) * smoothstep(0, 0.15, visibleFraction-gate)
```

三轴正弦的频率由哈希取在 `[0.6, 1.4] × driftSpeed`，互相不成整数比，因此不会出现周期性"整齐划一"。
用正弦而不是噪声，是为了保持逐粒子 O(1) 的解析求值。

`emission.window` 控制出生铺开的时间：例如 `[0, 8]` 表示 8 秒内逐渐出现，取默认 `[0,0]` 时按 `duration` 铺开。循环时 `emission.lifetime` 决定单颗停留多久，新粒子在不同相位持续出生，不会等到一轮结束再整批重来。`emission.count` 是体积内的粒子总数上界，平均出生密度约 `count / window`。

**随机流**：`JITTER`、`TIME`、`PHASE(7)`、`SIZE`、`COLOR`

**预设**

| 名称 | 关键参数 |
| --- | --- |
| 星尘 | `box=[24,10,24], count=180, driftAmplitude=0.4, visibleFraction=0.5` |
| 萤火 | `mode=["bob","flicker"], bobAmplitude=1.2, flickerRate=0.25, visibleFraction=0.35` |
| 舞台底雾 | `box=[30,4,30], count=120, driftSpeed=0.05, sizeJitter=0.6, blend="alpha"` |

**示例**

```json
{
  "style": "astrorbitsparticle:ambience",
  "duration": 600.0,
  "loop": true,
  "emission": { "count": 180, "window": [0, 12], "lifetime": 600.0, "lifetimeJitter": 0.0 },
  "physics": { "gravity": 0.0 },
  "appearance": {
    "sprite": "minecraft:glow",
    "size": 0.12,
    "sizeJitter": 0.35,
    "color": "#B7C9FF",
    "alphaByAge": [[0, 0.0], [0.05, 1.0], [0.95, 1.0], [1, 0.0]],
    "blend": "alpha"
  },
  "params": {
    "box": [24, 10, 24],
    "mode": ["drift", "bob", "flicker"],
    "driftSpeed": 0.15,
    "driftAmplitude": 0.4,
    "bobAmplitude": 0.35,
    "flickerRate": 0.12,
    "visibleFraction": 0.5
  }
}
```

**备注**

- `loop=true` 时粒子在不同相位持续出生，`lifetime` 决定单颗停留多久；不会整批消失或在周期边界重置。
- 填充速度由 `emission.window` 控制，粒子密度由 `emission.count` 与 `box` 体积控制，`visibleFraction` 再乘一层同时可见比例。
- 这是唯一建议把 `blend` 设为 `alpha` 的样式：大量叠加发光会在远处糊成一片。

### 3.9 `rain` 雨

**视觉目标**：大范围内大量粒子朝同一方向、无横向偏移地落下，速度有差异形成层次感，
粒子沿运动方向拉出轻微扩散的尾迹。

**参数**

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `direction` | vec3 | `[0.12,-1,0]` | 下落方向，内部归一化；X/Z 分量制造斜雨 |
| `speedRange` | [num,num] | `[14,22]` | 速度区间（块/秒），差速来源 |
| `area` | vec3 | `[26,18,26]` | 降雨体积（块） |
| `streakLength` | num | 0.8 | 保留未使用；拖尾用 `appearance.stretch` |
| `trailCount` | int | 0 | 每条雨丝额外挂的尾迹粒子数（0 表示只靠拉伸） |
| `trailSpread` | num | 0.08 | 尾迹横向扩散（块） |
| `wrap` | bool | true | 体积内循环，实现持续降雨 |

**运动学**

```text
dir      = normalize(direction)
speed_i  = lerp(speedRange, h(SPEED,i))
base_i   = O + (vec3(h(JITTER,i,100), h(JITTER,i,101), h(JITTER,i,102)) - 0.5) * area
v0_i     = dir * speed_i
p_i(t)   = base_i + ∫ v0_i + g - drag*(v - wind) dt      // 按 local_i 积分
wrap:    p_i = O + mod(p_i - O + area/2, area) - area/2      // 逐轴取模
```

每滴雨在体积内取随机起点，再按自己的存活时间沿 `direction` 下落；所有雨丝方向一致，位置随机分布在 `area` 内。`speedRange` 是初速度，`physics.gravity` / `drag` / `wind` 照常参与积分：重力让雨滴加速，`drag` 给出终端速度 `g/drag + wind`，适合做匀速雨幕。`wrap` 让雨幕在体积内持续循环。尾迹由 `appearance.stretch` 的拉长面片实现；`trailCount > 0` 时再在 `-dir` 方向补挂若干自身更小、更淡、带 `trailSpread` 横向偏移的粒子。

**随机流**：`SPEED`、`JITTER(3)`、`LIFE`、`SIZE`、`COLOR`

**预设**

| 名称 | 关键参数 |
| --- | --- |
| 细密小雨 | `speedRange=[10,14], area=[30,20,30], count=900, streakLength=0.5` |
| 暴雨 | `speedRange=[22,30], area=[36,24,36], count=1800, streakLength=0.9` |
| 斜雨 | `direction=[0.45,-1,0.1], speedRange=[16,20], count=1200` |

**示例**

```json
{
  "style": "astrorbitsparticle:rain",
  "duration": 900.0,
  "loop": true,
  "emission": { "count": 1200, "lifetime": 900.0, "lifetimeJitter": 0.0 },
  "physics": { "gravity": -4.0, "drag": 0.3 },
  "appearance": {
    "sprite": "minecraft:splash_0",
    "size": 0.14,
    "color": "#8FB8FF",
    "alphaByAge": [[0, 0.0], [0.05, 0.55], [0.95, 0.55], [1, 0.0]],
    "stretch": 0.035,
    "blend": "alpha"
  },
  "params": {
    "direction": [0.12, -1, 0.0],
    "speedRange": [14.0, 22.0],
    "area": [26, 18, 26],
    "streakLength": 0.7,
    "trailCount": 0
  }
}
```

**备注**

- `rain` 使用 `physics.gravity` / `drag` / `wind`。纯重力会让雨滴越落越快，想要接近匀速的雨幕就加 `drag`，终端速度约为 `g/drag + wind`。
- 逐轴取模会在体积边界产生瞬移。把 `area` 做得比 `viewDistance` 大，或让 `alphaByAge`
  在体积边缘淡出，可以完全掩盖。
- 中途加入时 `base_i + dir*speed_i*local_i` 是闭式函数，直接采样即可得到与老玩家一致的雨幕。
- `rain` 的 `trailCount` 与通用 `trail` 是两层机制：前者是同一发射序号下的固定偏移子粒子，后者按历史时刻回溯；同时开启会叠加粒子数。

## 4. 组合用法

样式可以任意组合：同一原点、同一 `duration` 叠加播放，服务端为每个特效分配独立的 seed。

| 组合 | 做法 |
| --- | --- |
| 双螺旋 | 单个 `spiral` 设 `strands=2`；或用两个 `spiral`，`phase` 分别为 0 / 180 |
| 冲击波 + 碎屑 | `spherical_burst(fill=0)` + `radial_burst(speedJitter=0.4)` |
| 流星雨 | `comet` × 3–5，`velocity` 略作变化，起点错开 |
| 舞台底噪 | `ambience` 常驻 + `rain` 做段落切换 |
| 收尾 | `radial_burst(speed="12*(1-u)")` 减速 + `wave` 衰减 |

组合的代价是每个特效独立占一份粒子预算，服务端按 `visibility.viewDistance` 分别过滤。
单个场景建议同时活跃的特效不超过 12 个、总粒子数不超过 20000。

## 6. 校验规则

定义文件在加载时校验，任一条不满足则该定义被拒绝并记录原因：

| 规则 | 说明 |
| --- | --- |
| `style` 已注册 | 未知样式直接拒绝 |
| `duration` ∈ [0.05, 3600] | 必须是常量，不允许表达式 |
| `count` ∈ [1, 8192] | 必须是常量整数 |
| `lifetime` ∈ [0.05, 3600] | 单粒子寿命 |
| 单客户端可见粒子总数 ≤ 20000 | 超出时客户端按距离降 LOD，不拒绝定义 |
| 表达式长度 ≤ 256，变量只允许 `t/d/u/n` | 解析失败回退到字段默认值并记一次日志 |
| 曲线 `u` 严格递增且 ∈ [0,1] | 端点缺失时自动补 0 / 1 |
| 颜色分量 ∈ [0,1] | 非法值钳制 |
| `viewDistance` ∈ [8, 512] | 服务端过滤半径 |
| `trail` 字段越界 | `interval` ∈ [0.01, 10]、`distance` ∈ [0.01, 16]、`lag` ∈ [0.01, 16]、`cap` ∈ [1, 32]、`spread` ∈ [0, 8]、`sizeScale` / `alphaScale` ∈ [0, 1]，越界钳制 |

## 7. 版本与兼容

- 样式 id 发布后不改名；语义变更走新 id（如 `radial_burst_v2`）。
- **RNG 版本**：`hash64` 算法和样式的随机流取用顺序都属于协议的一部分。
  改动其中任何一项都要提升 `rngVersion`，并保证新旧客户端各算各的、不串味。
- 本表 v1 对应 `rngVersion = 1`，协议版本见 [架构设计](架构设计.md) 5.2。
- 玩家进入游戏时服务端发送握手包，客户端比对 `protocolVersion` 与 `rngVersion`。不一致时客户端丢弃特效、记 warn，并在聊天栏提示。

## 9. 播放控制与贴图

`loop: false` 播放一轮后服务端移除、客户端清除。`loop: true` 每经过一个 `duration` 重新发射一轮，前一轮的粒子按自身寿命自然淡出，不会整批重置。

客户端按 `emission.lifetime` 的上界（含 `lifetimeJitter`）估算存活窗口，正向循环时回溯该窗口覆盖的周期，最多 8 个；每个周期用 `age - k*duration` 采样后追加到同一缓冲区，样式按 `local`/`life` 过滤掉已经结束的粒子。`comet` 不按周期重新生成粒子，循环时仍只采样当前相位；`ambience` 按周期持续补充随机出生的粒子。

`timeScale` 是播放速度倍率，负数倒放。反向循环（`reverse` 或负 `timeScale`）仍按 `duration` 取模采样，不会跨周期保留粒子。

`/astrorticle effect stop` 停止发射但保留已有粒子：循环特效固定在停止时的周期，不再进入新周期；停止时刻之后出生的粒子被过滤，已有粒子按各自寿命继续运行到结束。`/astrorticle effect clear` 立即清空全部特效与定义缓存。自然结束和离开可见范围仍立即移除，不走停止后的尾部。

开启 `trail` 后，客户端在源粒子之后追加轨迹粒子：time 模式取 `age - k*interval`，distance 模式在 `lag` 内按路径距离取点。历史年龄走与主采样相同的周期取模、正向回溯与反向换算；轨迹段只保留历史时刻仍存活的粒子，尺寸与不透明度按段衰减。轨迹粒子计入同一缓冲区和渲染预算，单特效上限 16384 颗，超出时截断更早的段。

`appearance.sprite` 可以写贴图 id，也可以写原版粒子定义 id（如 `end_rod`），后者取该定义 `textures` 数组里的贴图。

`spriteVariation` 决定多贴图怎么选：

- `particle`：每颗粒子按 SPRITE 流随机一张，默认，接近原版；
- `effect`：整个特效按种子共用一张；
- `cycle`：每 2 tick 轮换下一张，用于让静态变体呈现动画。

图集动画：带 `.mcmeta` 的贴图由 `TextureAtlas` 每 tick 重绘，粒子的 UV 始终是整块 sprite，不需要逐帧计算。Sodium 的“Animate Only Visible Textures”只上传被标记为可见的精灵，本模组在提取渲染状态时把本帧用到的动画精灵标记为可见，因此该选项开启时动画照常播放；未安装 Sodium 时不标记。
