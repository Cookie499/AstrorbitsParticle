# 接口文档

> 面向其他模组。API 版本 `1`，对应模组 `1.0.0`。

## 1. 依赖接入

发布仓库是 <https://github.com/NMB-Court-Team/Maven>，用原始文件地址作为 Maven 仓库：

```groovy
repositories {
    maven {
        name = "nmbMaven"
        // 仓库改成 GitHub Pages 时换成 https://nmb-court-team.github.io/Maven/
        url = uri("https://raw.githubusercontent.com/NMB-Court-Team/Maven/main")
    }
}

dependencies {
    // 需要在本模组存在时才能运行
    modImplementation "io.github.nmb-court-team:astrorbitsparticle:1.0.0"
}
```

仓库默认分支不是 `main` 时，把 URL 里的 `main` 换成实际分支。

可选集成（模组不存在时也要能启动）改用 `modCompileOnly`，调用前判断：

```kotlin
if (FabricLoader.getInstance().isModLoaded("astrorbitsparticle")) {
    // 调用 API
}
```

`fabric.mod.json` 按集成方式加依赖：

```json
"depends": { "astrorbitsparticle": ">=1.0.0" }
```

本地调试可以不推仓库，直接发到本机 Maven，坐标相同：

```text
.\gradlew.bat publishToMavenLocal
```

```groovy
repositories { mavenLocal() }
```

### 发布到仓库（维护者）

`publish` 默认输出到 `build/maven-repo`，也可以直接写进 Maven 仓库的本地克隆：

```text
git clone https://github.com/NMB-Court-Team/Maven.git ../Maven
.\gradlew.bat publish -Pnmb_maven_repo=..\Maven
cd ..\Maven
git add .
git commit -m "add astrorbitsparticle 1.0.0"
git push
```

产物路径是 `io/github/nmb-court-team/astrorbitsparticle/<version>/`，包含 jar、sources jar 与 pom。

## 2. 快速开始

在服务端线程生成一个已配置好的特效：

```kotlin
val id = AstrorbitsApi.spawnConfigured(
    Identifier.fromNamespaceAndPath("astrorbitsparticle", "radial_burst"),
    level,
    player.position(),
)
if (id == null) {
    // 定义不存在或校验失败，日志里有原因
}
```

Java 调用：

```java
Long id = AstrorbitsApi.spawnConfigured(definitionId, level, pos, 1.0f, null);
```

临时定义可以直接传 JSON：

```kotlin
val id = AstrorbitsApi.spawnJson("""
    {
      "style": "astrorbitsparticle:ring_burst",
      "duration": 3.0,
      "emission": {"count": 400, "lifetime": 2.4},
      "appearance": {"sprite": "minecraft:spark_0", "size": 0.24, "color": "#B388FF"},
      "visibility": {"requireScene": false},
      "params": {"speed": 8.0}
    }
""", level, player.position())
```

## 3. 方法

| 方法 | 说明 |
| --- | --- |
| `parseDefinition(json): Result<EffectDefinition>` | 解析并校验定义，失败返回 `Result.failure` |
| `parseDefinitionOrNull(json): EffectDefinition?` | 同上，供 Java 使用 |
| `definition(id): EffectDefinition?` | 读取 `config/astrorbitsparticle/effects` 里已加载的定义 |
| `spawnConfigured(definitionId, level, origin, scale, seed): Long?` | 按定义 id 生成，返回特效 id |
| `spawn(definition, level, origin, scale, seed): Long?` | 用已解析的定义生成 |
| `spawnJson(json, level, origin, scale, seed): Long?` | 解析并生成，一步完成 |
| `stop(effectId): Boolean` | 停止单个特效 |
| `stopAll()` | 停止全部特效 |
| `activeEffects(): List<EffectInfo>` | 当前活跃特效快照 |
| `scenes(): List<SceneInfo>` | 已加载场景快照 |
| `definitions(): Set<Identifier>` | 已加载定义的 id 集合 |
| `registerStyle(style): Boolean` | 注册自定义样式，id 冲突返回 `false` |
| `styles(): List<StyleSchema>` | 全部样式的参数声明 |
| `style(id): StyleSchema?` | 单个样式的参数声明 |

`seed` 传 `null` 时用服务端随机数；传入固定值可以复现同一段画面。

## 4. 线程与生命周期

- 所有方法都要在服务端线程调用。网络线程或其他线程先切到 `server.execute { ... }`。
- 特效在下述情况被移除：播放结束、`stop`/`stopAll`、`/astrorbits reload`、服务器关闭。
- 调用 `registerStyle` 要在使用该样式的特效生成之前；两端都要注册。
- 定义只在服务端解析，客户端通过启动包拿到 JSON 后自行绑定。

## 5. 自定义样式

实现 `ParticleStyle`，注册后即可在定义里用 `mymod:twinkle`。

```kotlin
object TwinkleStyle : ParticleStyle {
    override val id = "mymod:twinkle"

    override val schema = StyleSchema(
        id, "闪烁",
        params = listOf(
            numSpec("speed", 4f, "扩散速度（块/秒）", "0..32", 0f, 32f),
            numSpec("spread", 0.5f, "随机扩散比例", "0..1", 0f, 1f),
        ),
    )

    class Params(val speed: BoundNumber, val spread: Float) : BoundStyle

    override fun bind(binder: Binder): BoundStyle =
        Params(binder.num("speed"), binder.number("spread"))

    override fun sample(effect: BoundEffect, origin: Vec3, seed: Long, age: Float, out: ParticleBuffer) {
        val params = effect.styleParams as Params
        val dir = FloatArray(3)
        for (i in 0 until effect.count) {
            val life = EmissionMath.lifetime(effect.emission, seed, i)
            val local = age - EmissionMath.birth(effect.emission, seed, i, effect.count)
            if (local <= 0f || local >= life) continue
            StyleMath.sphereInto(dir, seed, i)
            val distance = params.speed.at(age) * local
            StyleSupport.emit(
                effect, seed, i, age, local / life,
                (origin.x + dir[0] * distance).toFloat(),
                (origin.y + dir[1] * distance).toFloat(),
                (origin.z + dir[2] * distance).toFloat(),
                out,
            )
        }
    }
}

// 初始化阶段，两端都执行
AstrorbitsApi.registerStyle(TwinkleStyle)
```

契约：

- `sample` 必须只依赖 `(seed, age, index)`，不能保存跨帧状态。客户端中途加入时会直接按当前 `age` 采样，状态式样式会看到错误画面。
- 粒子通过 `out.push(x, y, z, size, alpha, argb)` 写入，坐标是世界坐标。
- `schema` 是默认值、范围校验和文档的唯一来源；`binder` 从它取默认值，未知参数会被拒绝。
- 样式 id 发布后不要改名；语义变化用新 id。

## 6. 数据格式

- 定义字段与 9 种内置样式的参数见 [样式参数](样式参数.md)。
- 运动学、随机流与 JSON 示例见 [粒子样式表](粒子样式表.md)。

- 特效定义支持 `subEffect`（目标定义 id）与 `subEffectTrigger`（`end` 或 `impact`），字段说明见 [配置](配置.md)。
- 进入服务器时服务端发送 `astrorbitsparticle:handshake`，携带协议与 RNG 版本；客户端不一致时清空特效并提示，不再渲染。
- `/astrorbits reload` 会重新读取 `config.json` 的上限，不需要重启服务器。

## 7. 当前没有提供的接口

- 运行时增删场景（场景只从 `config/astrorbitsparticle/scenes.json` 读取）。
- 生成、停止、可见性变化的事件钩子。
- 数据包形式的定义热载（定义只从配置目录读取）。
- 客户端渲染钩子（粒子的纹理由定义里的 `appearance.sprite` 决定）。

`API_VERSION` 与网络协议版本相互独立；新增方法不改变 `API_VERSION`，破坏兼容的签名变更才递增。
